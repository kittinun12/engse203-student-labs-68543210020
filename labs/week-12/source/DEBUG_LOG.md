## BUG #0 · รายละเอียด 10 ตัวอักษรพอดีติด Error

- **อาการ:** เมื่อส่งข้อมูลคำร้องที่มีรายละเอียด (details) ความยาว 10 ตัวอักษรพอดี ระบบตอบกลับ error บอกว่ารายละเอียดไม่ครบถ้วน
- **วิธีทำซ้ำ:** เรียกใช้ `validateRequestInput()` โดยส่งวัตถุที่มี `details: '1234567890'` (10 ตัวอักษร)
- **เครื่องมือ:** Vitest (Unit Test)
- **สาเหตุ (ไฟล์:บรรทัด):** `src/validators/requestValidator.js` เงื่อนไขใช้ `< = MIN_DETAILS` ทำให้ความยาว 10 โดนปฏิเสธไปด้วย
- **วิธีแก้:** เปลี่ยนเงื่อนไขการตรวจสอบความยาวเป็น `< MIN_DETAILS`
- **test ที่กัน:** `test('10 ตัวอักษรพอดี → ผ่าน (ค่าขอบ)')` ใน `requestValidator.test.js`

## BUG #1 · ลบคำร้องแล้วเพิ่มใหม่ ได้ 500

- **อาการ:** เมื่อลบรายการคำร้องตรงกลางออก แล้วทำการสร้างคำร้องใหม่ เซิร์ฟเวอร์ตอบกลับ 500 Internal Server Error
- **วิธีทำซ้ำ:** ยิง `DELETE /api/requests/REQ-003` แล้วตามด้วย `POST /api/requests` ด้วยข้อมูลที่ถูกต้อง
- **เครื่องมือ:** Vitest + Supertest (Integration Test) / Postman
- **สาเหตุ (ไฟล์:บรรทัด):** `src/services/requestService.js` ฟังก์ชัน `nextId()` คำนวณจาก `COUNT(*) + 1` เมื่อลบรายการกลางออก ทำให้ได้ ID ซ้ำกับรายการสุดท้ายที่มีอยู่เดิมใน DB (เกิด Primary Key Conflict)
- **วิธีแก้:** แก้ไขฟังก์ชัน `nextId()` ให้ค้นหาตัวเลขรหัสที่มากที่สุดที่มีอยู่จริงในฐานข้อมูล (`Math.max`) แล้วบวกเพิ่ม 1
- **test ที่กัน:** `test('BUG #1: ลบรายการตรงกลางแล้วเพิ่มรายการใหม่ → ตอบ 201')` ใน `requests.api.test.js`

## BUG #2 · Dashboard แสดง "กำลังดำเนินการ 0"

- **อาการ:** หน้า Dashboard แสดงผลตัวนับรายการสถานะ "กำลังดำเนินการ" เป็น 0 ทั้งที่มีข้อมูลคำร้องสถานะกำลังดำเนินการอยู่ในระบบ
- **วิธีทำซ้ำ:** โหลดหน้า Dashboard เมื่อมีข้อมูลคำร้องที่เป็นสถานะกำลังดำเนินการอยู่
- **เครื่องมือ:** Vitest (Frontend Test) / Chrome DevTools
- **สาเหตุ (ไฟล์:บรรทัด):** `src/utils/requestSummary.js` ฟังก์ชัน `summarizeRequests` ใช้คีย์ string เป็น `'in progress'` (เว้นวรรค) ซึ่งไม่ตรงกับคีย์ในฐานข้อมูลที่เป็น `'in-progress'` (มีขีดกลาง)
- **วิธีแก้:** แก้ไขข้อความคีย์สถานะใน `requestSummary.js` จาก `'in progress'` เป็น `'in-progress'`
- **test ที่กัน:** `test('นับสถานะ in-progress ถูกต้อง (BUG #2)')` ใน `requestSummary.test.js`

## BUG #3 · เปลี่ยนสถานะคำร้องที่ไม่มีอยู่ ได้ 500

- **อาการ:** เมื่อส่งคำขออัปเดตสถานะของคำร้องที่ไม่มีรหัสอยู่ในระบบ เซิร์ฟเวอร์ตอบกลับ 500 แทนที่จะเป็น 404
- **วิธีทำซ้ำ:** ยิง `PUT /api/requests/REQ-999` พร้อม body `{ "status": "completed" }`
- **เครื่องมือ:** Vitest + Supertest (Integration Test)
- **สาเหตุ (ไฟล์:บรรทัด):** `src/controllers/requestController.js` ในฟังก์ชัน `updateRequestStatus` มีการเรียกใช้ `console.log(updated.id)` ก่อนจะตรวจสอบการมีอยู่ของ `updated` ส่งผลให้เกิด `TypeError: Cannot read properties of null`
- **วิธีแก้:** ย้ายการตรวจสอบ `if (!updated)` ขึ้นมาไว้ก่อนการเรียกใช้ `updated.id` เพื่อส่ง Status 404 ออกไปทันทีเมื่อไม่พบรายการ
- **test ที่กัน:** `test('BUG #3: PUT เปลี่ยนสถานะคำร้องที่ไม่พบ → ตอบ 404')` ใน `requests.api.test.js`
