# บันทึกการใช้งาน AI ช่วยเหลือในการทำโปรเจกต์ (AI_USE.md)

**เครื่องมือ AI ที่ใช้งาน:** Google Gemini
**สัปดาห์ / งานที่ทำ:** Week 07 - REST API Validation & Error Handling

ในสัปดาห์นี้ ได้มีการใช้งาน AI เพื่อช่วยทำความเข้าใจและแก้ไขปัญหาต่างๆ ทั้งในฝั่ง Frontend (React) และ Backend (Express) โดยมีรายละเอียดการใช้งานดังนี้:

---

## ครั้งที่ 1

**ถามอะไร**
- ไม่แน่ใจว่าควรนำฟังก์ชัน `handleChangeStatus` และปุ่มสำหรับเปลี่ยนสถานะคำร้องไปวางไว้ใน Component ไหน (`RequestCard` หรือ `RequestDetailPage`) รวมถึงวิธีเขียนที่ถูกต้องเพื่อไม่ให้อัปเดตหน้าจอก่อน API ตอบสำเร็จ

**AI ตอบว่าอย่างไร (สรุปสั้น)**
- แนะนำให้นำไปใส่ใน `RequestDetailPage.jsx` เพราะมี State `request` และฟังก์ชัน `setRequest` เตรียมไว้อยู่แล้ว
- อธิบายการทำ "✓ ถูกต้อง" คือการใช้ `await` รอให้ Backend อัปเดตข้อมูลและส่งข้อมูลล่าสุดกลับมาก่อน จึงจะใช้ `setRequest(updated)` อัปเดตหน้าจอ เพื่อป้องกันข้อมูลฝั่ง Client และ Server ไม่ตรงกัน

**ใช้ส่วนไหน / แก้เองตรงไหน**
- นำโครงสร้างโค้ดปุ่มและฟังก์ชัน `handleChangeStatus` ไปใส่ใน `RequestDetailPage.jsx` และทำการผูก Event `onClick` พร้อมการจัดการ `disabled={isUpdating}` เพื่อกันผู้ใช้กดปุ่มซ้ำขณะรอ

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## ครั้งที่ 2

**ถามอะไร**
- 1. กดปุ่มเปลี่ยนสถานะแล้วขึ้น Error `400 Bad Request` (สถานะต้องเป็น pending, in-progress หรือ completed)
- 2. กดย้อนกลับไปหน้า Dashboard แล้วเจอ Error ใน Console `Cannot read properties of undefined (reading 'startTime')`

**AI ตอบว่าอย่างไร (สรุปสั้น)**
- **Error 400:** ชี้ให้เห็นว่าเกิดจากการส่งค่าจากปุ่มเป็นพิมพ์ใหญ่และมีช่องว่าง (`'In Progress'`, `'Completed'`) ซึ่งไม่ตรงกับที่ Backend คาดหวัง
- **Error startTime:** อธิบายว่า Error ลักษณะนี้ที่ชี้ไปที่ `VM...` หรือ `<anonymous>` มักไม่ได้เกิดจากโค้ดบั๊ก แต่เป็น Error จากส่วนขยาย (Extension) ของเบราว์เซอร์ เช่น React Developer Tools ที่แทรกแซงจังหวะเปลี่ยนหน้าจอ ซึ่งสามารถมองข้ามได้หากใช้งานบน Production จริง

**ใช้ส่วนไหน / แก้เองตรงไหน**
- แก้ไข String ใน `onClick` ให้เป็น `'in-progress'` และ `'completed'` รวมถึงเพิ่มคลาส CSS (`className="button in-progress"`, `className="button completed"`) ตามคำแนะนำเพื่อเปลี่ยนสีปุ่มให้ตรงกับสถานะ

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## ครั้งที่ 3

**ถามอะไร**
- สอบถามแนวทางการเขียนโครงสร้างและใช้งาน `AppError` และ `asyncHandler` ใน Express ตามโจทย์ที่ได้รับ โดยไม่แน่ใจว่าจะต้องสร้างไฟล์เหล่านี้ไว้ที่โฟลเดอร์ไหน และจะนำไปประยุกต์ใช้กับไฟล์ `requestController.js` อย่างไร (หรือถ้าไม่สร้างโฟลเดอร์ใหม่จะวางไว้ตรงไหนได้บ้าง)

**AI ตอบว่าอย่างไร (สรุปสั้น)**
- แนะนำให้นำไฟล์ไปไว้ใน `api/src/middleware/` ได้เลย
- ช่วย Refactor โค้ดใน `requestController.js` โดยเปลี่ยนจากการใช้ `res.status().json()` ซ้ำๆ ไปเป็นการใช้ `throw new AppError('ข้อความ', status)` แทน
- อธิบายประโยชน์ของ `asyncHandler` ในการช่วยครอบดักจับ Error จากการใช้ `async/await` อัตโนมัติ ป้องกันเซิร์ฟเวอร์ค้างโดยไม่ต้องเขียน `try...catch` ทุกๆ Route

**ใช้ส่วนไหน / แก้เองตรงไหน**
- สร้างไฟล์ `AppError.js` และ `asyncHandler.js` ตามที่ได้รับ และทำการแก้ไขไฟล์ `requestController.js` และ `requestRoutes.js` (รวมถึงแก้ไข `errorHandler.js` ตามที่โจทย์ระบุ) ด้วยตนเองโดยอ้างอิงหลักการที่ AI อธิบาย

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## ครั้งที่ 4

**ถามอะไร**
- ต้องการทำระบบ Auto-Retry ฝั่ง Frontend เมื่อ API ล่มชั่วคราว (Status 5xx) หรือติดต่อไม่ได้ (Status 0) ในไฟล์ `apiClient.js` ตามเงื่อนไขของโจทย์

**AI ตอบว่าอย่างไร (สรุปสั้น)**
- ให้ตัวอย่างการเขียนฟังก์ชัน `apiFetch` แบบ Recursion (เรียกตัวเองซ้ำ) 
- แนะนำการใช้ `setTimeout` ห่อด้วย `Promise` เพื่อทำระบบหน่วงเวลา (Backoff Delay) ก่อนลองยิง API ใหม่
- แนะนำให้กรองไม่ทำการ Retry หากเป็น Error ระดับ 400 หรือ 404 (Client Error) เพราะถือว่าคำขอผิดพลาดจากฝั่งผู้ใช้ ลองใหม่ก็ผิดเหมือนเดิม

**ใช้ส่วนไหน / แก้เองตรงไหน**
- นำแนวคิดฟังก์ชัน Retry ไปปรับใช้ใน `apiClient.js` และเรียนรู้วิธีการจัดการตัวแปรรอบ (`retries`) และเวลา (`delay`)

**เข้าใจโค้ดที่ได้มาไหม** ☑ เข้าใจทั้งหมด ☐ เข้าใจบางส่วน ☐ ยังไม่เข้าใจ

## สรุป

- **ส่วนที่เขียนเองทั้งหมด:**
  - การจัดโครงสร้างไฟล์และการเรียกใช้งาน Middleware ฝั่ง API
  - การจัดการ Validation Request ผ่าน `validateRequest.js`
  - การจัดรูปแบบ CSS และหน้าตา UI ของปุ่มเปลี่ยนสถานะ
- **ส่วนที่ AI ช่วย:**
  - ให้คำแนะนำการจัดการ State และ Event onClick สำหรับปุ่มเปลี่ยนสถานะใน React
  - อธิบายสาเหตุของ Error ทั้งในระดับ HTTP Status และ Error จาก Browser Extension
  - แนะนำการ Refactor Code ให้ใช้ `AppError` เพื่อจัดการ Error ระดับรวมศูนย์
  - แนะนำลอจิกการทำ Auto-Retry ด้วย Recursion

- **ส่วนที่ยังไม่มั่นใจ:** การทำงานเบื้องลึกของ `Promise` ตอนที่ทำ Auto-Retry (ยังต้องศึกษาเพิ่มเติมเพื่อให้เข้าใจกลไก Asynchronous ให้ลึกซึ้งยิ่งขึ้น)
